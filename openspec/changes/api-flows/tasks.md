# Tasks: API de flujos con Postgres (`api-flows`)

Fases secuenciales; cada una empieza cuando la anterior pasa su gate. Comportamiento en `specs/flows-api/spec.md` y `specs/flow-validation/spec.md`; cómo, en `design.md` (D1-D13 y «Contrato de API»). Cada `#### Scenario` de los dos deltas tiene un `it` con exactamente su título (lo comprueba el test único de cobertura de 4.9). Antes de la fase 1, el orquestador commitea solos los artefactos del cambio (`spec: …`); ninguna fase toca `src/` antes. Ningún fichero nuevo se llama con `credentials` ni `apikey` (los bloquea `guard_files`), y ninguno es un fichero de entorno (las guardas lo impiden; el de ejemplo lo crea una persona, 7.6). Un gate solo se marca con checks realmente ejecutados.
