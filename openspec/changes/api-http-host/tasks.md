# Tasks: salida http de producción de la API (`api-http-host`)

Fases secuenciales; cada una empieza cuando la anterior pasa su gate. **Revisión 2** tras el FAIL de `popi:architecture-reviewer` (B1-B4 y riesgos; ver la cabecera de `design.md`). Comportamiento en `specs/http-host/spec.md`, `specs/conversations-api/spec.md` y `specs/flow-engine/spec.md`; cómo, en `design.md` (D1-D24, «Contrato»). Cada `#### Scenario` de los tres deltas tiene un `it` con exactamente su título (`apps/api/test/spec-coverage.spec.ts` y `packages/engine/tests/conformance.test.ts`). Reglas para todas las fases:
- Ningún test ni mutante envía un paquete fuera de loopback ni necesita privilegios: toda conexión de la salida http en un test pasa por una `TestNetwork` (D18), y la lista de tests de cada mutante se elige para que un mutante que salte la costura vaya a loopback (D21). Ningún test llama a Anthropic.
- Ningún fichero nuevo es un fichero de entorno, lleva `credentials` o `apikey` en el nombre, ni guarda claves o certificados en disco (la PKI del test vive en memoria). Los valores de prueba tipo `Bearer …` llevan `// gitleaks:allow` si gitleaks los marca.
- Fuera de los ficheros de la tabla de D2, `git diff --stat main...HEAD` no lista nada (4.6).
- Un gate solo se marca con checks realmente ejecutados.
